# 울타리에서 사용자 차단

- 기존 회원 API POST /api/users/:userNo/block → POST /api/v1/users/:userNo/block를 재사용한다.
- 로그인 후 다른 사용자의 울타리에서 닉네임 오른쪽 더보기 메뉴에 차단하기를 표시한다. 내 울타리와 비로그인 화면에는 표시하지 않는다.
- 클릭하면 즉시 API 요청한다. 처리 중 버튼을 비활성화하고 차단 중 문구로 바꾼다. 성공하면 현재 울타리에서 소개말 아래를 차단한 유저입니다. 문구로 가린다.
- 기존 BE는 차단 추가/복구와 해당 사용자 사이의 팔로우 관계 및 관련 알림 삭제를 같은 트랜잭션에서 처리한다. 맞팔도 해제하며 차단 해제 시 팔로우는 자동 복구하지 않는다.
- 이미 차단된 응답은 완료 상태로 처리한다. 그 밖의 실패는 기존 알림 모달로 표시한다. 차단 해제는 기존 설정 > 차단한 사용자에서 지원한다.
- NeighborBlockIntegrationTest 3개에서 팔로우 및 알림 삭제, 맞팔 해제, 차단 해제 후 관계 미복구/재차단을 확인했다. 테스트 데이터는 롤백한다. DB 구조 변경 없음.

후속 방향별 검색·조회/404 정책은 [directional-block.md](./directional-block.md)를 따른다.

차단한 상대의 울타리 더보기 메뉴에서는 차단해제로 전환한다. 클릭 시 기존 DELETE /users/:userNo/block를 호출하고 현재 페이지의 프로필·펫·게시글 및 탭 데이터를 다시 조회한다. 공개 범위에 맞춰 콘텐츠를 표시하며 이전 팔로우는 복구하지 않는다. 처리 중 버튼은 해제 중...으로 표시하고 중복 요청을 막는다.
