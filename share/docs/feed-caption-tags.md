# 게시글 AI 승인 후 태그·피드 저장

2026-11-02 적용. DB 스키마 변경 없음. FE·BE 함께 배포한다.

## 작성·수정

1. FE는 본문에 해시태그를 포함해 POST/PATCH `/api/feeds`로 보낸다. 게시글 저장 전에 태그 생성 API를 별도로 호출하지 않는다.
2. BE는 본문 전체를 AI에 전달한다. 호환용 `tagIds`가 있으면 해당 태그명도 읽어 검사 문장에 추가한다. 본문에 이미 있는 태그명은 중복 추가하지 않는다. 이 단계에서는 태그·피드를 쓰지 않는다.
3. AI 부적절 판정은 `AI_CONTENT_BLOCKED`, 장애·시간 초과는 `AI_CHECK_UNAVAILABLE`로 차단한다. 수정 거절 시 기존 본문과 태그 연결을 유지한다. 검사 이력은 기존 정책대로 별도 저장한다.
4. 승인 후 트랜잭션에서 본문의 해시태그를 추출하고 기존 태그를 재사용한다. 없는 태그는 USER/NONE으로 생성하고 게시글·태그 연결·사용 횟수·승인 상태와 함께 저장한다. 저장 실패 시 새 태그까지 롤백한다.

본문에서 공백 또는 시작 위치 뒤의 `#영문숫자한글_` 토큰을 추출한다. 태그명은 2~30자이며 대소문자를 무시해 본문 내 중복을 제거한다. 한 글자 토큰은 본문에 그대로 남지만 태그 생성·연결에서 제외한다. 호환용 tagIds에 기존 한 글자 태그 ID가 있어도 연결하지 않으며 승인 본문 복구에도 같은 규칙을 적용한다. 본문은 해시태그 포함 최대 500자, 연결 태그는 최대 30개다.

수정 시 본문을 전달하면 그 본문을 기준으로 해시태그 연결을 갱신한다. 본문을 비우면 본문 유래 태그 연결도 해제한다. 본문과 tagIds를 모두 생략하면 기존 연결을 유지한다. tagIds만 전달하면 기존 호환 동작대로 해당 연결로 교체하며, 그 태그명도 AI 검사 대상이다. 본문과 tagIds를 함께 전달하면 합집합을 연결한다.

이미 연결된 태그는 기존 ID를 우선 재사용하며 기존 보류 태그를 새 태그로 다시 만들지 않는다. 새로운 연결의 거절·미승인 상업 태그 사용 제한은 유지한다. 태그 자체를 관리하는 별도 API는 유지한다.

댓글·답글은 기존처럼 먼저 저장하고 비동기로 검사한다. 사진 태그(펫 멘션)는 본문 해시태그와 별개이며 기존 동작을 유지한다.

## 검증

- AI 거절/장애 시 피드 저장 및 새 태그 생성 차단
- 본문 밖 tagIds의 태그명도 함께 검사
- 승인 시 신규 태그 생성·연결, 대소문자 중복 제거, 재수정 시 사용 횟수 중복 증가 방지
- 피드 저장 실패 시 신규 태그와 피드의 동시 롤백
- 본문에서 삭제한 태그 연결 해제 및 기존 보류 태그 ID 유지
- FE 작성·수정 성공/거절 모두 별도 태그 생성 요청 없음
