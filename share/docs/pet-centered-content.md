# 닉네임태그와 주인공 펫

## 닉네임태그

- API/DB의 nickname 필드명은 유지하고, 본문은 영문 소문자·밑줄 1~10자로 저장한다. 중복은 기존 UNIQUE와 중복 확인 API로 차단한다.
- 화면에서는 공통 nicknameTag로 @를 한 번 붙인다. 가입·회원정보 수정은 @를 보여주되 요청에는 본문만 전송한다.
- 소셜 가입 자동 태그도 소문자로 생성한다. 기존 30일 변경 제한은 유지한다.
- 2026-10-28 현재 DB의 34개 계정을 번역/축약했다. 예: 울타리→ultary, 나리집사→nari_owner, 산책러→walker, 펫샵→petshop.
- 새 울타리 URL은 /myultary/ultary 등이다. 과거 닉네임 URL의 별도 리다이렉트는 이번 변경에 포함하지 않았다.
- 기존 댓글·답글 및 승인 본문의 @이전닉네임 19개 행을 전환하고 언급 복구용 해시 스냅샷을 추가했다. 과거 AI 요청/판정 로그는 이력으로 보존한다.

## 주인공 펫

- 034_content_pet.sql을 서버 변경 전에 적용한다. 기존 사진 좌표 언급과 다른 ultary_content_pet 관계를 사용한다.
- 게시글 작성/수정과 스토리 JSON 등록: subjectPetIds 배열. 최대 20마리, 본인의 활성 펫만 선택 가능. 순서 보존·중복 제거.
- 게시글 수정 시 subjectPetIds 생략은 유지, 빈 배열은 해제. 펫 미지정 등록도 허용하며 계정 태그로 표시한다.
- 읽기 응답: FeedResponse, StoryResponse, StoryOwnerResponse.subjectPets에 petId/name/profileFile을 반환한다.
- 게시글은 사진 태그 바로 아래, 스토리는 이미지 위에서 선택한다. 공통 SubjectPetPicker 사용. 선택은 unread, 미선택은 read 테두리.
- 작성 중 화면 이동/크롭 시 선택을 보존하고, 새 작성/완료/초기화 시 해제한다. 게시글 수정 진입 시 기존 선택을 복원한다.
- 메인 스토리 링·피드·스토리 상세에서 펫 이름을 먼저, 계정 태그를 작게 표시한다. 펫 미지정 시 이름 자리는 닉네임태그만 남기고, 주인공 영역의 태그 색상은 gray-100을 사용한다. 첫 번째 펫 사진이 있으면 대표 이미지로 사용한다.
- 현재 DB 피드 21건(37개 연결), 스토리 16건(24개 연결)에 소유 펫 1~3마리를 배정했다.
- 펫이 없는 상점 계정 3개의 피드 12건은 다른 사람의 펫을 연결하지 않고 유지했다. 사용자 결정에 따라 펫 미지정 상태와 닉네임태그 표시만 유지한다.
- 복구용 백업과 적용 스크립트는 BE .local-backups/nickname-subject-* 및 nickname-subject-migration.cjs에 있다. Git에 포함하지 않는다.

## 2026-10-28 공통 펫 표시·스토리 카드 스택

- [펫이름들과닉네임태그]의 구현은 src/components/common/PetNamesAndNicknameTag.tsx. 첫 줄은 쉼표로 나열한 펫 이름, 다음 줄은 @닉네임태그(gray-100). 펫이 없으면 태그만 표시한다. 검색 강조, 개별 펫 클릭, 계정 클릭을 지원한다.
- 검색/최근 검색/팔로우·팔로워/DM 새 상대·공유/사진 언급/댓글 언급 추천에서 재사용한다. 사용자 목록 이름은 관리 순서다. 최신 정책에서는 펫태그 검색을 제거하고 선택은 petId로 연결한다.
- 검색·최근 검색·팔로우/팔로워·공유 대상 API에 petNames를 추가했다. 공유 대상 pets 항목에도 name을 추가했다. 닉네임태그·펫 이름을 검색할 수 있다.
- 메인 스토리에는 해당 계정의 활성 스토리에 실제 연결된 펫을 ID로 중복 제거하고 관리 순서로 표시한다. 이름이 같더라도 다른 펫이면 각각 표시한다. 첫 관리 순서 펫이 카드 스택 맨 앞에 온다.
- PetProfileGroup.tsx는 stack/row 형태를 지원한다. 메인은 카드 스택, 피드·스토리 상세는 콘텐츠에 선택된 펫 사진을 한 스토리 프레임 안에 가로로 표시한다. 목록이 길면 내부 가로 스크롤을 사용한다.
- 일반 사용자 대표 사진은 첫 번째 활성 펫으로 고정한다. 1번 펫에 사진이 없어도 2번 사진을 대신 쓰지 않으며 기본 프로필을 표시한다.
- 스토리 URL에 이전 nickname 힌트가 남아 있더라도 현재 API의 작성자 닉네임태그를 우선한다.
- 이번 단계는 DB 스키마/데이터 변경 없음. API/조회 SQL 변경이 있어 FE·BE 모두 반영해야 한다.
- 검증: BE 전체 179개·FE 전체 179개 테스트, 전체 lint·TypeScript·FE 운영 빌드·BE WAR 통과. 실제 공통 컴포넌트를 별도 로컬 검사 화면에서 렌더링해 카드 스택·가로 프로필·쉼표/두 줄 배치를 확인한 뒤 임시 화면을 제거했다.

## 2026-10-28 다중 계정·연결 울타리·펫태그 종료

- 계정당 활성 펫은 최대 3마리. FE에서 추가를 막고 BE는 계정 행 잠금 후 개수를 검사해 동시 요청도 제한한다. 기존 펫은 삭제하지 않았다.
- 연락처·이메일 중복을 허용하고 닉네임태그 UNIQUE는 유지한다. 035_multi_accounts_and_ultary_links.sql을 현재 DB에 적용했다. 기존 DB에서는 001이 아닌 035를 한 번 적용한다. 현재 연결 DB에는 중복 실행하지 않는다.
- 로그인은 연락처/이메일과 비밀번호가 모두 일치하는 활성 계정만 선택 목록으로 반환한다. 일치 계정이 하나면 바로 로그인하며 여러 개면 공통 action 모달에서 @닉네임태그를 고른다. 선택 전 토큰·쿠키 발급 없음, 선택 후 비밀번호와 계정 소속을 다시 검사한다.
- 휴대폰 인증 기반 비밀번호 복구도 계정을 고른 후 선택된 계정의 비밀번호와 세션만 변경한다. 소셜 로그인은 provider 사용자 ID 연결 기준을 유지한다.
- 소개 아래 다른 울타리 링크는 공개 계정을 닉네임태그/펫 이름으로 검색해 추가·삭제한다. 본인 링크·차단 관계·비공개 대상 추가는 거절한다. 이후 비공개/탈퇴한 대상은 방문자에게 숨기고 소유자에게는 삭제할 수 있게 남긴다.
- API: GET /users/{userNo}/ultary-links (공개 조회), GET /my-ultary/links/search?q=, POST /my-ultary/links {targetUserNo}, DELETE /my-ultary/links/{targetUserNo}. BE 접두사는 /api/v1, BFF는 /api.
- 펫태그 입력·변경·쿨다운 API와 개발 메뉴를 제거했다. 검색은 펫 이름·닉네임태그 기준이며 예전 mention_id로는 검색되지 않는다. 해시태그 검색은 유지한다.
- 사진·스토리 언급의 위치와 petId 연결은 그대로 보존하고 라벨만 펫 이름으로 바꾼다. 동일 이름도 petId로 선택한다. 외부 JSON에는 mentionId/petTags를 노출하지 않는다. DB의 기존 mention_id 컬럼은 호환을 위한 내부 값으로만 유지하며 새 펫에는 임의 내부 키를 생성한다.
- FE·BE 함께 배포하고 로컬 BE도 재시작해야 새 API가 적용된다. 커밋/실제 서버 배포는 수행하지 않았다.

- 최종 검증: BE 186개 테스트(실패 0), FE 182개 회귀 테스트(실패 0), 전체 ESLint·독립 TypeScript 검사·FE 운영 빌드·BE ultary.war 생성 통과. 계정 선택 전 쿠키 미발급과 선택 후 원래 비밀번호 재검증 요청도 검사했다.

## 2026-10-28 울타리 펫별 피드 선택

- 울타리 머리말은 @닉네임태그, 펫 상세는 이름·성별·소개만 표시하며 펫태그는 표시하지 않는다.
- 콘텐츠 탭 순서는 일반 피드 → 언급 피드 → 고정 피드. 실제 탭 변경 시 펫 선택과 상세 표시를 해제한다.
- 처음에는 펫 미선택으로 전체 목록을 표시한다. 한 마리인 계정도 동일하다. 일반/언급 탭에서 펫을 고르면 해당 펫이 주인공/협업/사진 언급으로 연결된 게시글만 조회한다.
- 펫 사진을 다시 누르거나 전체 피드 보기로 선택 해제한다. 고정 탭에서 펫을 누르면 일반 탭으로 이동해 선택하며 고정 탭에는 필터를 적용하지 않는다.
- GET /api/v1/users/{userNo}/pet-feeds?petId=&tab=feed|tagged&limit= (BFF /api/users/{userNo}/pet-feeds)를 추가했다. SQL에서 공개 범위·차단과 펫 관계를 먼저 적용한 후 최신순 LIMIT를 적용한다. 다른 울타리의 펫 ID·고정 탭 요청은 거절한다. 게스트는 공개 계정/공개 글만 조회한다.
- 새 DB migration은 없다. FE·BE 모두 반영해야 새 조회 API를 사용할 수 있다.
- 검증: 펫별 조회 전 필터링·게스트/회원 공개 범위·차단 통합 검사, 탭 이동·선택/해제·고정 탭 전환 회귀 검사, 전체 FE lint·TypeScript·운영 빌드 통과. 실제 공개 화면에서 @닉네임태그·미선택 상태·탭 순서를 확인했다.

## 다른 울타리 연결 UI

- 검색 모달은 대표 프로필(45px), 관리 순서의 펫 이름, 닉네임태그를 표시한다. 울타리의 연결 목록은 @닉네임태그와 X를 한 묶음으로 나열하며 묶음 단위로 줄바꿈한다. 기본 grass-650, hover/active는 grass-700과 밑줄을 사용한다.
- 목록·검색 API의 Link 응답에 petNames, profileFile, hasStory, hasUnviewed를 추가한다. 공개·접근 가능 계정만 상세 정보를 반환하며 사용할 수 없는 연결은 해당 정보를 비운다.
- 검색 팝업의 프로필은 스토리 테두리를 표시하지 않는다. 검색 결과를 선택하면 팝업을 닫고 연결 목록에 즉시 추가하며 울타리로 이동하지 않는다. 추가 API가 실패하면 해당 항목만 되돌리고 울타리 추가 실패! 모달에 서버 오류 이유를 표시한다. 연결 목록의 X는 확인 모달에서 삭제를 승인하면 즉시 목록에서 제거하고 연결 해제 API를 호출한다. 실패하면 원래 위치에 복원하고 울타리 삭제 실패! 모달에 오류 이유를 표시한다. 다른 사람의 울타리에서는 추가·삭제 버튼을 표시하지 않는다.
