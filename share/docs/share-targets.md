# 사용자 추천 목록과 우선순위 (2026-10-27)

API: GET /api/v1/dm/share-targets, BFF: GET /api/dm/share-targets.

## 공통 정렬

1. 현재 내가 팔로우 중인 사용자 안에서 아래 화면별 활동 순위를 적용한다. 해당 활동이 없으면 나머지 팔로우를 팔로우 최신순으로 배치한다.
2. 내가 팔로우하지 않는 사용자에게 같은 활동 순위를 적용한다. 활동 이력이 없는 나머지 팔로워는 팔로우받은 최신순으로 마지막에 배치한다.
3. 동일 활동 순위는 최신 활동순, 시각까지 같으면 userNo 내림차순이다. 한 사용자는 가장 높은 조건에 한 번만 나온다.

최근 활동은 현재 시각 기준 1개월 이내다. 언급 유저는 댓글·답글에서 내가 언급한 사용자와 나를 언급한 사용자를 합친 그룹이다. 독립 언급 그룹에서는 내가 언급한 사용자가 우선이고, 각 방향 안에서 최신순이다.

| 화면 / mode | 1순위 | 2순위 | 3순위 | 4순위 |
|---|---|---|---|---|
| 댓글·답글 / COMMENT_MENTION | 언급 유저 | DM | 내 스토리 태그 | 내 피드 태그 |
| 새 DM / DM | DM | 언급 유저 | 내 스토리 태그 | 내 피드 태그 |
| 피드 DM 공유 / SHARE (기본) | DM | 언급 유저 | 내 스토리 태그 | 내 피드 태그 |
| 스토리 업 / STORY_TAG | 내 스토리 태그 | DM + 언급 최신 활동 | 내 피드 태그 | 공통 후순위 시작 |
| 게시글 사진 태그 / FEED_TAG | 내 피드 태그 | DM + 언급 최신 활동 | 내 스토리 태그 | 공통 후순위 시작 |

사진·스토리의 2순위는 DM·내가 언급·나를 언급한 기록의 최댓값으로 비교한다. 이 혼합 그룹에서는 활동 종류보다 최신 시각이 우선이다.

댓글·답글의 feedId를 전달하면 해당 게시글에 댓글·답글을 작성한 사람도 기존 활동 추천 뒤, 나머지 팔로워 앞에 추가한다. 참여 이력은 1개월 제한 없이 최신 작성순이며 삭제된 댓글·답글은 제외한다. 중복 사용자는 높은 기존 활동 순위에 한 번만 나온다. 게시글 조회 권한을 먼저 검사하고, 차단·정지·언급 차단 필터를 적용한다. 팔로우 사용자 우선 정책은 유지한다.

공통 후순위: 나를 스토리에 태그 → 나를 피드에 태그 → 최근 내가 팔로우 → 최근 나를 팔로우 → 나머지 팔로우 → 나머지 팔로워. 위의 팔로우 여부 분리가 이 활동 순위보다 항상 우선한다.

응답 group은 화면 내 활동 그룹 번호다. COMMENT_MENTION은 1~11, DM/SHARE는 1~10, 사진·스토리는 1~9, 사진·스토리에서 본인은 맨 마지막 group=99다. 팔로우 여부가 group보다 먼저 정렬되므로 응답 전체의 group 번호는 단조 증가하지 않을 수 있다.

## 후보와 검색

- limit 기본 30, 최대 50. q는 닉네임/활성 펫 mentionId 부분 검색이며 앞 @·양끝 공백·대소문자를 무시한다. 검색 후 정렬·limit을 적용한다.
- 차단 관계 양방향, 탈퇴/정지 사용자, 삭제된 콘텐츠·펫은 제외한다. 오래된 DM/태그/언급만 있고 팔로우 관계도 없는 사용자는 제외한다.
- 언급 이력은 ultary_feed_comment_mention의 mentioned_user_no와 작성자를 연결한다. 부모 댓글/게시글이 삭제된 답글도 이력에서 제외한다. 유지된 언급은 수정 시 최초 연결 시각을 보존하고, 삭제된 언급은 추천 이력에서도 제거한다.
- COMMENT_MENTION은 언급을 허용한 사용자만 추천한다. 사진·스토리는 활성 펫이 있고 태그를 허용한 사용자만 표시하며 본인 펫은 마지막에 포함한다.
- 기존 priorityOrder=DM,OWN_STORY_TAG,OWN_FEED_TAG 계약은 세 값 순열로 유지한다. 내부적으로 DM 뒤에 언급 그룹을 붙이며, 태그 모드의 DM은 DM+언급 혼합 그룹이다. COMMENT_MENTION은 언급 그룹을 가장 앞에 둔다.
- 항목은 userNo, nickname, petTags, pets, profileFile, dmRoomId, following, followedBy, group, activeAt. petTags에는 @가 없고 활성 펫 priority 순서다.
- AccountSearchList는 항목 순서를 유지한다. showSearch=false이면 검색창 없이 목록만 표시한다. 전송 권한·태그 선택 권한의 기존 정책은 유지한다.

## 댓글·답글 언급 저장 및 알림

- 작성/수정 JSON의 content와 명시적으로 선택한 mentions: [{userNo}]만 전달한다. 추천 선택과 답글 달기 버튼으로 추가한 상대는 실제 언급으로 저장한다. 직접 타이핑·스페이스만으로 완성한 @닉네임은 일반 텍스트이며 서버에서 사용자 ID로 자동 변환하지 않는다. 본문에서 사라진 대상 ID만 보내도 언급으로 남기지 않는다.
- 별도 언급 테이블에 댓글 또는 답글 ID, 대상 userNo를 저장한다. 중복 대상은 하나다. 수정 시 유지된 연결 시각을 보존하고 없어진 연결은 제거한다. 선택 정보의 안전한 AI 복구를 위해 033_comment_mention_snapshot.sql을 먼저 적용한다. 현재 공용 DB에는 적용 완료했으며 기존 데이터는 변경하지 않았다.
- FE에서 @는 처음 또는 공백 뒤에서만 추천 입력을 시작한다. 입력 중에는 임시 강조하고, 추천을 클릭하지 않은 채 공백/blur로 끝내면 일반 텍스트로 돌아간다. 추천 클릭으로 선택한 언급만 앞쪽 언급 묶음으로 이동하며 커서는 원래 본문 위치로 복귀한다. 선택한 언급만 전체 삭제 단위/저장 대상이며, 지운 뒤 다시 직접 타이핑해도 일반 텍스트다.
- 알림 문구: XXX가 댓글에서 나를 언급하였습니다. / XXX가 답글에서 나를 언급하였습니다. 인용은 기존 알림 정책인 최대 40자이며 해당 댓글/답글로 이동한다.
- 같은 답글의 원댓글 작성자에게는 일반 답글 알림을 우선하고 REPLY_MENTION 알림을 중복 생성하지 않는다. 원댓글 작성자가 게시글 작성자이기도 하면 기존 게시글 통합 알림을 사용한다. 그 외 원댓글 작성자에게는 FEED_COMMENT 타입, COMMENT_REPLY:{replyId} 키, hasReply=1로 알린다.
- 알림 설정과 차단 정책을 적용한다. 유지된 언급의 본문 수정은 기존 알림의 읽음 상태를 초기화하지 않는다. AI가 수정 내용을 거절해 승인 본문을 복구하면 언급 연결도 승인 본문에 맞춰 복구한다.
- 운영 웹소켓 미사용 정책은 유지한다. 알림은 DB에 저장되며 알림 목록 조회로 확인하고, 로컬 실시간 환경에서는 기존 웹소켓 배지도 사용한다.

댓글·답글 추천 UI는 @ 입력 시 최초 추천 대상 최대 50명을 받은 후 해당 목록 안에서 닉네임/펫태그를 즉시 필터링한다. 결과가 없으면 추천리스트 없음을 표시한다. 언급 확정 후 커서는 앞쪽 언급 묶음이 아니라 원래 본문을 쓰던 지점으로 복귀한다.

## 2026-10-30 중복 추천 제외·답글 자동 언급·시연 데이터 보충

- 입력 본문에 이미 들어간 닉네임은 추천 목록에서 제외한다. 단, 현재 완성 중인 @토큰 자체는 제외 기준에서 빼서 정확히 일치하는 추천도 선택할 수 있다. 같은 닉네임이 다른 위치에 이미 있으면 현재 입력과 무관하게 제외한다. 펫 이름·닉네임태그 일치 강조와 기존 추천 순서는 유지한다.
- 답글 달기는 실제 누른 댓글/답글 작성자를 명시적으로 언급한다. 초록색·굵기·통째 삭제·mentions 전송을 추천 선택과 동일하게 적용한다. 본인 작성 항목에는 본인 언급을 넣지 않는다. 안내와 답글 소속은 기존대로 원댓글 기준이다.
- 사용자 요청으로 삭제되지 않은 답글 128개 중 기존 실제 언급 7개를 보존하고 70개에 추가해 77개(60.2%)로 맞췄다. 신규 연결은 원댓글 상대 45개·같은 게시글의 다른 참여자 25개이며, 38개 피드에 분산했다. 활성 사용자·언급 허용·차단 관계·삭제된 부모를 검사했다.
- 본문과 사용자 ID 연결, 본문 해시별 언급 복구 스냅샷을 함께 저장했다. 기존 연결과 삭제된 답글은 유지하며 기존 알림의 인용만 동기화하고 새 알림은 만들지 않았다. AI 작업·승인 상태·좋아요·작성 시각·알림 읽음 상태를 바꾸지 않았다.
- 적용 전 백업·변경안·복구 SQL은 Git 제외 `.local-backups/reply-mentions-20261030/`에 보관한다. DB 데이터는 반영 완료이며 FE 변경은 새 실행/빌드·배포가 필요하다.
