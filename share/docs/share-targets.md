# 공유 대상 검색과 우선순위

`GET /api/v1/dm/share-targets` (BFF `/api/dm/share-targets`)

- `limit`: 기본 30, 최대 50.
- `q`: 닉네임 또는 활성 펫 mentionId의 부분 검색. 앞 @·양끝 공백·대소문자를 무시한다. SQL 바인딩으로 처리하며 %, _는 와일드카드가 아니다. 검색을 먼저 적용하고 정렬 후 limit을 적용한다.
- `priorityOrder`: 앞 3개 그룹의 순서. `DM,OWN_STORY_TAG,OWN_FEED_TAG` 기본값. 세 값을 중복 없이 모두 지정한다. 그 외는 400.

| 기본 순위 | 조건 | 그룹 내 시각 |
|---|---|---|
| 1 | 최근 1개월 내 DM 상대 | 마지막 메시지 |
| 2 | 최근 1개월 내 내 스토리에 태그한 상대 | 마지막 태그 |
| 3 | 최근 1개월 내 내 피드에 태그한 상대 | 마지막 태그 |
| 4 | 최근 1개월 내 나를 스토리에 태그한 상대 | 마지막 태그 |
| 5 | 최근 1개월 내 나를 피드에 태그한 상대 | 마지막 태그 |
| 6 | 최근 1개월 내 내가 팔로우한 상대 | 팔로우 시각 |
| 7 | 최근 1개월 내 나를 팔로우한 상대 | 팔로우받은 시각 |
| 8 | 나머지 팔로우 | 팔로우 시각 |
| 9 | 나머지 팔로워 | 팔로우받은 시각 |

한 사람은 가장 앞 그룹에서 한 번만 표시한다. 그룹 내 최신순, 동률이면 userNo 내림차순. 맞팔도 중복되지 않는다. 오래된 DM만 있거나 오래된 태그만 있는 상대는 포함하지 않는다. 만료됐지만 삭제하지 않은 스토리는 최근 태그 이력에 포함한다. 콘텐츠·펫 삭제, 탈퇴 계정, 양방향 차단, 자기 자신은 제외한다. 스토리 태그는 ultary_story_mention, 피드 태그는 ultary_feed_pet 및 ultary_feed_media_mention에서 보호자 userNo를 연결한다.

응답 `petTags`는 활성 펫의 mentionId 배열(@ 없음)이며 펫 priority 순서다. 태그는 최종 대상들을 일괄 조회한다. 후보 조회는 SELECT만 사용하며 DB 스키마 변경은 없다.

## 화면 공통 컴포넌트

`AccountSearchList<T>`는 검색 입력창부터 스크롤 목록까지 담당한다. 항목에는 userNo, nickname, imageUrl, petTags(@ 포함)를 전달한다. 로딩·오류·빈 결과를 표시하고 일반 선택 및 라디오 선택을 지원한다. API 조회와 순위 계산은 호출자가 담당하며 입력받은 항목 순서를 유지한다. 기본 로컬 검색, `serverSearch` 사용 시 서버 검색 결과를 그대로 표시한다.

`ShareMessageSheet`는 공통 컴포넌트를 사용하고 250ms 검색 디바운스와 이전 요청 결과 무시를 처리한다. 선택 후 검색어를 바꾸면 대상을 다시 선택하도록 초기화한다. 보내는 중에는 검색·대상 변경을 막는다. `priorityOrder` prop으로 앞 세 그룹의 순서를 설정할 수 있다. 나머지 그룹은 공통 정책을 유지한다.

기존 메시지 권한 정책은 유지한다. 태그 관계만 있고 팔로우·팔로워·기존 대화방이 없는 상대는 목록에 안내와 함께 표시되지만 선택할 수 없다. 기존 생성·전송 API도 그대로 사용한다.


## 화면별 모드

`mode=SHARE|DM|STORY_TAG|FEED_TAG` (기본 SHARE). 공유·DM은 DM → 내 스토리 태그 → 내 피드 태그 순, 스토리 언급은 내 스토리 태그 → DM → 내 피드 태그 순, 피드 사진 언급은 내 피드 태그 → DM → 내 스토리 태그 순으로 앞 3단계를 적용한다. 4~9단계는 동일하다. 명시적 priorityOrder가 있으면 모드 기본 순서보다 우선한다.

태그 모드는 활성 펫이 있고 태그를 허용한 계정만 표시한다. 본인 펫은 본인의 태그 차단 설정과 무관하게 선택할 수 있도록 목록 끝(group=10)에 추가한다. 본인도 닉네임·펫태그 검색으로 찾을 수 있다. DM·공유 모드에서는 자기 자신을 제외한다.

응답 pets는 `[{petId, mentionId}]`로 개별 펫 선택에 사용한다. petTags와 동일한 priority 순서이며 일괄 조회한다. AccountSearchList의 onSelectPetTag로 태그별 선택 UI를 활성화한다. 스토리·피드 태그 검색에는 취소 버튼이 없고 뒤로가기로 닫는다. 기존 전역 검색 대신 해당 관계 목록 안에서 서버 검색한다.

프런트 useRankedAccounts는 3개 화면의 조회·검색·취소된 응답 무시를 공통 처리한다. /dm의 기존 팔로우/팔로워 탭은 통합 대화 상대 목록으로 교체했다. 태그 관계만 있는 상대는 표시되지만 기존 DM 정책상 새 대화 및 전송은 팔로우 관계가 필요하다.
