# 관리자 신고 원문 미리보기

- `/admin/reports/{reportId}`의 상세 스크롤 영역을 신고 정보/피드의 두 열로 나눈다. 오른쪽 Feed는 최대 430px이며 좁은 화면에서는 세로로 배치한다.
- Feed의 `readOnly` 모드는 작성자 사진·닉네임을 표시하되 스토리·울타리 이동을 비활성화하고 액션 중 댓글 보기만 노출한다. 사진 캐러셀, 본문 펼치기, 태그 설명은 유지한다.
- 댓글·답글은 읽기 전용이며 입력창, 답글 달기, 더보기·신고 메뉴, 공감 버튼과 사용자 링크를 숨긴다. 댓글창은 피드 영역 안에 열리고 관리자 페이지 URL/history를 바꾸지 않는다.
- 댓글·답글 신고는 해당 항목을 자동으로 펼쳐 강조한다. 일반 사용자 화면의 기본 동작은 유지한다.

## API

- `GET /api/v1/admin/reports/{reportId}/preview`: `{ feed, comments, tags }`. FE BFF 경로는 `/api/admin/reports/{reportId}/preview`.
- 기존 관리자 JWT 인증을 사용하며 일반 사용자 토큰은 거부한다. 신고에 연결된 게시글만 조회한다. USER 신고는 피드 미리보기를 사용하지 않는다.
- 댓글·답글 신고는 실제 부모 관계를 따라 피드를 찾는다. 공개 범위·회원 정지·신고 대상의 소프트 삭제와 관계없이 보관된 원문을 확인할 수 있다. 대상이 아닌 삭제 댓글·답글은 제외한다.
- 미리보기 조회 자체는 신고 상태·좋아요·스토리 열람 이력을 변경하지 않는다. 상세 입장 시 기존의 REQUESTED→CONFIRMED 처리는 유지한다.
- `GET /api/v1/admin/reports/{reportId}/files/{fileId}/content`: 관리자 인증 + 해당 미리보기의 미디어/프로필/태그 이미지에 포함된 파일만 허용한다. unrelated 파일은 404. BFF도 관리자 쿠키를 사용하며 캐시는 `private, no-store`.
- 관리자 상대 경로 이미지는 전용 프록시로 표시하고 Next 이미지 최적화 대신 브라우저가 관리자 쿠키를 보내도록 한다. 사용자 파일 공개 정책은 변경하지 않는다.
- 삭제되거나 사용할 수 없는 연결 태그는 설명 목록에서 생략하고 피드 원문은 유지한다. DB 스키마 변경 없음.

## 검증

- AdminReportPreviewIntegrationTest 4개 통과: 각 신고 종류의 부모 피드 조회, 삭제·정지 원문 보존, 관리자/사용자 인증 구분과 조회 시 상태 불변, 파일 연결 검사, 존재하지 않는 신고 거부.
- FE 타입 검사, 태그/스토리 회귀 5개 통과. 신규 관리자 파일과 BFF 린트 오류 없음. 기존 MediaImage alt 전달 경고 및 Feed/CommentSheet의 기존 ref·effect 린트 오류는 별도 정리 대상.
- 브라우저 검증용 데이터를 사용해 읽기 전용 버튼 구성, 피드 안 댓글창, 태그 설명 팝업을 확인했다. 실사용 관리자 로그인 세션으로 전체 흐름을 검증한 것은 아니다. 임시 UI 검증 페이지는 제거했다.
