# 회원 관리·관리자 처리 이력

## 화면과 메뉴

- `/admin/users`: 관리자 메뉴의 첫 항목. 대표 펫 프로필(45px, 스토리 표시 없음), 회원번호, 닉네임태그, 반려동물 이름, 정상/정지/탈퇴 상태, 가입일, 활성 펫·게시글 수, 받은 신고 수를 보여준다. 반려동물은 닉네임태그와 상태 사이에 관리 순서(priority, pet_id)로 쉼표 구분하여 나열한다. 없는 경우 `–`로 표시한다.
- `/admin/users/{userNo}`: 마스킹한 연락처·이메일, SNS 연결 여부, 등록 펫, 최근 게시글/받은 신고(각 최대 20개)를 표시한다. 비밀번호·토큰·소셜 제공자 식별자를 조회 응답에 포함하지 않는다.
- 목록·상세에서 정지/해제를 할 수 있다. 화면에서 사유 입력과 확인 모달을 거친다. 탈퇴 회원은 조치 버튼을 표시하지 않으며, 기존 정지/해제 API도 탈퇴 회원 복원을 허용하지 않는다.
- `/admin/actions`: 관리자 첫 화면에서는 일반 메뉴 아래 36px 간격, 목록 사이드바에서는 로그아웃 바로 위 하단에 표시한다. 관리자·처리 대상 검색과 대상 종류 필터를 제공한다.
- 기존 태그·신고·AI 메뉴의 숫자 표시는 유지한다. 별도 운영 현황 화면이나 회원 관리용 처리 대기 건수는 추가하지 않는다.

## API

모두 관리자 JWT 전용이며 BFF 공유 키·관리자 인증 경로를 그대로 사용한다. BFF는 아래 Spring 경로의 `/api/v1/admin`을 `/api/admin`으로 바꾼 경로다.

| Method | Spring 경로 | 내용 |
|---|---|---|
| GET | `/api/v1/admin/users?q=&status=&page=&size=` | 닉네임태그·활성 반려동물 이름 부분 검색·회원번호 일치 검색, 상태 필터 |
| GET | `/api/v1/admin/users/{userNo}` | 회원 상세 |
| POST | `/api/v1/admin/users/{userNo}/suspend` | 정지, JSON `{ "reason": "사유" }` |
| POST | `/api/v1/admin/users/{userNo}/unsuspend` | 정지 해제, JSON `{ "reason": "사유" }` |
| GET | `/api/v1/admin/users/{userNo}/files/{fileId}/content` | 해당 회원의 활성 펫 프로필 파일만 허용, private/no-store |
| GET | `/api/v1/admin/actions?q=&targetType=&page=&size=` | 관리자 처리 이력 |

- 회원 상태: `ALL`(기본), `ACTIVE`, `SUSPENDED`, `WITHDRAWN`.
- 이력 대상: `ALL`(기본), `USER`, `TAG`, `REPORT`, `AI_REVIEW`.
- `page`는 0부터 시작한다. `size` 기본 10, 범위 1~50. 두 목록 응답은 `{items,totalCount,page,pageSize}`이며 검색·필터가 목록과 전체 건수에 동일하게 적용된다.
- 회원은 회원번호 내림차순, 이력은 처리일시·처리이력번호 내림차순이다. 화면은 기존 공통 Pager와 높이에 맞는 페이지 크기를 사용한다. 반려동물 이름이 여러 개 일치해도 EXISTS 검색으로 회원/전체 건수가 중복되지 않는다.
- 회원 목록/상세의 `petNames`는 삭제되지 않은 펫의 이름 배열이다. 목록에서는 펫 이름을 일괄 조회하며 회원별 추가 쿼리를 만들지 않는다.
- `q` 최대 100자. 검색의 `_`, `%`는 와일드카드로 처리하지 않는다. 사유는 최대 500자이며 UI는 빈 사유 제출을 막는다. 기존 정지/해제 API의 본문 없는 호출은 호환한다.
- 목록의 게시글 수는 삭제되지 않은 게시글만 센다. 받은 신고는 회원 본인·해당 회원 작성 게시글·댓글·답글을 대상으로 한 모든 상태의 신고다. 상세에서는 관리자 확인을 위해 비공개/삭제 콘텐츠의 최근 내역도 표시한다.

## 이력 저장과 배포

- 새 테이블: `ultary_admin_action_log`. 기존 DB에는 `037_admin_action_log.sql`과 `038_admin_action_log_samples.sql` 적용, 새 DB의 `001_init_schema.sql`은 v40다. 현재 연결된 DB에는 두 migration을 적용했다. 새 실제 조치는 기본값 `is_sample=0`으로 저장된다.
- 기록 대상은 회원 정지/해제, 태그 승인/거절/대기 복귀, 신고 확인/거절/삭제/회원 정지, AI 오류 유지/삭제/대기 조치다. 관리자 로그인/로그아웃·단순 조회는 처리 이력에 포함하지 않는다.
- 관리자 번호·로그인ID·이름 스냅샷, 조치 종류, 대상 번호·표시명, 태그 요청 번호(전달된 경우), 변경 전후 상태, 사유와 처리일을 저장한다. 이메일·전화번호·비밀번호·토큰·AI 원문을 이력에 복제하지 않는다.
- 조치와 이력 INSERT는 동일 트랜잭션이다. 조치 실패는 이력을 남기지 않으며, 이력 저장 실패도 실제 조치를 롤백한다. 수정·삭제 API는 제공하지 않는다.
- 실제 처리 이력은 BE 반영 후 실행한 새 조치부터 기록된다. 사용자의 별도 요청으로 과거 처리일을 토대로 구성한 예시 35건(태그 27, 신고 7, AI 수동 조치 1)을 보충했다. API `sample=true`와 목록의 ‘예시 이력’ 표시로 실시간 기록과 구분한다. 변경 전 상태·설명과 원본에 없는 처리자 배정은 시연용이며, 처리일·현재 처리 결과는 원본을 사용한다. 원본에 처리일이 없는 대기 건은 만들지 않는다.
- 보충 SQL은 `../database/seed/mariadb_10_1/001_admin_action_log_samples.sql`이다. `sample_source_key` 고유값으로 재실행 중복을 방지하고 이미 실제 이력이 있는 같은 조치는 건너뛴다. 실제 태그·신고·AI 원본의 상태/날짜를 바꾸지 않는다.
- 보충 전 백업과 복구 SQL은 Git 제외 `.local-backups/admin-history-samples-20261030/`에 보관한다. 트랜잭션 적용, 원본 해시 보존, 재실행 추가 0건을 검증했다. 통합 검증 픽스처는 롤백하여 실제 회원을 정지하거나 테스트 기록을 남기지 않는다.
- FE·BE 둘 다 재실행/배포해야 이름 표시·검색·예시 구분을 사용할 수 있다.

## 검증

- 직전 BE 전체 회귀 213개 통과. 이후 반려동물 검색·관리 순서·삭제 펫 제외·중복 건수 방지와 예시 구분·처리일 정렬 검증을 추가하여 관리자 통합 검사 11개를 실행했다.
- FE 관리자 관련 회귀 12개, ESLint·TypeScript 및 SCSS 컴파일 검사로 확인한다.
