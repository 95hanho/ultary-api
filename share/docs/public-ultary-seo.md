# 공개 울타리와 페이지 제목

- `/myultary/{nickname}` 단건 루트는 비로그인 접근 가능. 하위 게시글·팔로우 목록·작성·수정 경로는 기존 로그인 정책 유지.
- `GET /api/v1/public/ultaries/{nickname}`은 사용자 토큰 없이 BFF 키로 조회하는 전용 API. 공개·활성 계정만 반환하며 비공개·존재하지 않는 계정은 404.
- 응답은 닉네임·소개·펫 공개 프로필·팔로우 건수·전체 공개 게시글 수·피드/고정/태그 그리드. 비밀번호·이메일·전화번호·지역·조회자 관계 정보는 제외.
- 그리드 최대 50개씩. `PUBLIC` 게시글만 노출하며 태그/고정된 글은 실제 작성자의 계정 공개 여부도 적용. 게스트 클릭은 `/feeds/{id}` 공유 화면으로 이동.
- 게스트는 로고와 로그인 버튼만 표시. 팔로우·메시지·신고·하단 메뉴는 숨기며 스토리 등 로그인 기능은 열지 않는다.
- 파일 content GET은 optional auth. 익명 요청은 공개·활성 계정의 활성 펫 프로필 또는 PUBLIC 게시글 미디어에 현재 연결된 파일만 허용. 일반 사용자 API와 BFF 키 검증은 유지.
- 공개 프로필 API와 익명 파일 응답은 no-store. 서버 데이터 요청도 no-store, React cache는 같은 렌더 요청 내 중복 조회만 제거.

## 메타데이터

- 울타리: `nickname(@pet1,@pet2)님의 울타리 - Ultary`. 펫이 없으면 괄호 생략. 공개 페이지는 서버에서 제목·소개·canonical·OG 기본 정보를 생성.
- 비공개·조회 실패 울타리는 noindex. 로그인한 본인/다른 계정의 화면 제목도 조회 후 동일 형식 적용.
- 스토리: 요청 표기 그대로 `스토리 - Ultray` (목록형 뷰어 및 단건 뷰어).
- 검색: `검색 - Ultary`, 알림: `알림 - Ultary`. 모두 noindex.
- 그 외 페이지는 `Ultary`. 관리자도 같은 제목, 기존 noindex 유지.
- 절대 URL 기준은 APP_URL. 운영 도메인 설정이 필요하다.

## 추후 결정

운영 도메인과 대표 공유 이미지를 정한 뒤 공개 게시글별 OG, robots/sitemap, 검색 도구 등록을 진행할 수 있다. 현재 메인 `/`의 비로그인 로그인 이동 정책은 유지한다. DB 스키마 변경은 없다.
