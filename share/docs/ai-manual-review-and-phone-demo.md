# AI 장애 처리와 데모 인증번호

## 태그 요청 거절

- 거절 태그는 USER/REJECTED로 표시한다. 기존 피드 연결은 유지하고, 작성용 검색·추천·태그 생성 재사용·신규 피드 연결은 거부한다. 대기로 바꾸면 COMMERCIAL/PENDING, 승인하면 COMMERCIAL/APPROVED다.
- 작성 화면의 본문 태그 자동완성은 전체 피드 검색 대신 작성용 `/tags/search`를 사용한다. 전체 검색에서 기존 피드를 찾는 정책은 유지한다.
- 기존 피드의 같은 태그를 유지하는 수정은 허용한다. 거절 태그의 소개·이미지·링크는 숨겨 설명 팝업도 열리지 않는다.

## 추천과 부적절 검사

- 태그 추천은 동기로 총 3회까지 호출한다. 정상적인 빈 결과만 기존 DB 추천으로 보완하며, 3회 실패하면 503 AI_CHECK_UNAVAILABLE과 서비스 오류 안내를 반환한다. 호출 실패 로그는 각 시도마다 남긴다.
- 작성 화면 안내: 서버 오류로 태그 추천을 잠시 사용할 수 없습니다. 불편을 드려 죄송합니다. 잠시 후 다시 시도해 주세요.
- 모델/제공자 타임아웃은 유지한다. 3회 대기를 허용하도록 추천 요청만 BFF 65초, 브라우저 70초 제한을 사용한다. 다른 요청 제한은 유지한다.
- 게시글 작성·수정은 저장 트랜잭션 전에 동기로 AI 검사한다. 통과한 경우만 저장하고 승인 기준 본문을 기록한다. AI_CONTENT_BLOCKED(400)면 사유 모달을 닫은 뒤 본문에 포커스한다. AI_CHECK_UNAVAILABLE(503)면 작성/수정하지 않고 오류 로그를 독립 저장한다. 전 과정에서 전체 로딩을 표시한다.
- 댓글·답글은 내용과 durable 검사 작업을 같은 DB 트랜잭션에 저장한 뒤 응답한다. AI 호출은 작업자가 별도로 처리한다.
- 실패 시도는 즉시 오류 로그에 남고, 기존 3회 재시도 정책을 유지한다. 인프라 오류만으로 콘텐츠를 삭제하거나 작성자에게 부적절 판정 알림을 보내지 않는다. 실제 부적절 판정은 기존 숨김/수정 복구 정책을 사용한다.

## 관리자 오류 처리

- 관리자 AI 오류 로그는 FAILED를 조회하며 대상은 전체/태그 추천/게시글/댓글/답글 중 선택한다. 같은 작업의 재시도는 한 행으로 표시한다.
- 목록과 상세에 검사 당시 본문을 표시한다. 작업 본문 또는 요청 로그의 inspection_content를 사용하며, 과거에 미보관한 본문은 기록 없음으로 표시한다. 프롬프트와 Gemini 응답 원문은 제공하지 않는다.
- 태그 요청·신고·AI 오류 목록에서 상세와 같은 상태 선택 기능을 제공한다. 태그 거절은 사유 필수다. 링크와 선택 영역을 분리하며, 조치 후 메뉴 건수를 다시 조회한다.
- 저장 전 검사 오류는 아직 저장 대상/작업이 없으므로 유지·삭제조치를 제공하지 않는다.
- `POST /api/v1/admin/ai/logs/{aiRequestId}/review`, JSON `{status: PENDING|KEPT|DELETED}`. BFF는 같은 경로에서 `/api/v1` 대신 `/api`를 사용한다.
- 같은 작업의 오류 시도들은 처리 상태를 공유한다. 확인 대기/유지/삭제조치를 선택하며, 관리자가 조치하면 자동 검사 작업을 SKIPPED로 마쳐 진행 중 작업이 뒤늦게 덮어쓰지 못하게 한다.
- 최신 본문 버전·작성자·피드 연결을 잠근 뒤 확인한다. 수정·삭제된 대상 또는 삭제된 부모 댓글에는 이전 오류 기록으로 조치할 수 없다.
- 작업 생성 시 실제 대상의 게시글 ID·작성자·본문을 검증하며 불일치 시 작업을 등록하지 않는다. 관리자 조치 오류는 게시글 연결 불일치, 부모 게시글 삭제, 대상 삭제, 본문/버전 불일치, 부모 댓글 삭제를 구분해 안내한다. 검증 조건을 우회해 삭제하지 않는다.
- 유지는 승인 기준 본문으로 저장한다. 삭제는 소프트 삭제하며 기존 댓글 수·알림 정리와 실시간 갱신을 수행한다. 목록·상세 모두 삭제조치 후 유지/확인 대기로 변경할 수 있다. 이 작업으로 삭제한 원문은 최신 버전·작성자·본문·부모가 유효하고 다른 신고/오류의 삭제조치가 없을 때 복구한다. 댓글 수는 실제 복구 시 한 번만 증가시키고 스레드 알림을 동기화하며 실시간 복구를 알린다. 확인 대기로 변경해도 자동 검사 작업은 SKIPPED로 유지한다. 보관된 오류 로그는 유지한다.
- 메뉴 오류 수는 관리자 처리 완료(유지/삭제조치) 작업을 제외한다. 목록에는 처리 완료 행도 회색으로 남겨 이력을 볼 수 있다.
- DB v38 `032_ai_inspection_content.sql`: ultary_ai_request_log.inspection_content 추가. 사전 검사한 미저장 초안도 본문을 보관한다.
- DB v37 `031_ai_manual_review.sql`: 작업의 admin_review_status/admin_reviewed_at/admin_reviewed_by 추가 및 기존 거절 태그 상태 보정.

## 휴대폰 데모

- `auth.phone.demo-mode`로 제어하며 환경변수는 PHONE_AUTH_DEMO_MODE다. 공통·운영 기본 false, local 기본 true.
- 데모에서만 휴대폰 인증 요청 응답에 demoCode를 포함한다. 정상 모드에는 필드 자체를 생략한다. 실제 SMS 발송 연결은 추가하지 않았다.
- 회원가입·비밀번호 재설정·회원정보 수정의 연락처/인증요청 바로 아래에 `데모모드 인증번호 : 123456`을 표시한다. 번호를 바꾸면 기존 코드를 지운다.
- 회원가입의 기존 프런트 인증 무조건 성공 분기를 제거했다. 데모 코드도 실제 저장된 번호와 일치해야 하며 토큰·만료 검증은 유지한다. 서버 로그에 코드는 출력하지 않는다.

## 회원가입 인증 안내

- 데모 인증 요청 성공은 데모 코드 한 번만 표시한다. 별도 성공 배너를 만들지 않는다.
- 일반 인증 요청 성공/실패와 인증 확인 성공은 연락처 아래, 인증 확인 실패/인증번호 누락은 인증번호 아래에 표시한다.
- 연락처 변경 시 인증 토큰·코드·안내·오류를 초기화하며 변경 전 비동기 응답은 무시한다.
- 필수값/형식 오류·중복 닉네임/이메일/전화번호는 해당 입력 아래에 표시한다. 회원가입 요청 자체의 서버/통신 오류만 상단에 남긴다.

## 검증

- BE 선택 테스트 42개: 추천 실패 3회·3회차 회복, 댓글·답글 작업 큐 등록, 관리자 처리·늦은 검사 결과 무효화·버전 보호, 오류 API 인증/필터, 태그 차단과 이전 승인 본문의 연결 복구, 데모 코드 정상·오입력 및 비데모 코드 비노출.
- FE 타입 검사와 변경 파일 린트 통과, 인증·울타리·태그 회귀 109개 통과. 실서비스 Gemini/SMS를 호출하는 테스트는 수행하지 않았다.
- 미사용 501 스켈레톤 5개(작성 임시 사진·편집 사진·사진 태그, 통합 설정 GET/PATCH)는 제거했다. 실제 게시/수정과 개별 설정 API를 사용한다.
