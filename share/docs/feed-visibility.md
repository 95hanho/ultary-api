# 게시글별 공개 범위

작성·수정 화면의 사진 태그 아래에서 `전체`, `팔로우`, `나만`을 선택한다.

- `PUBLIC`: 전체
- `NEIGHBORS`: 팔로우 관계 (기존 서버의 ACCEPTED 관계 판정 유지)
- `PRIVATE`: 작성자만

기존 `ultary_feed.visibility` 컬럼과 아래 API를 그대로 사용하므로 DB 마이그레이션은 필요 없다.

- `POST /api/v1/feeds`: 요청의 `visibility`를 저장한다. 생략하면 계정의 게시글 기본 공개 범위를 사용한다.
- `GET /api/v1/feeds/{feedId}`: 저장된 `visibility`를 반환하고 조회자의 접근 권한을 검사한다.
- `PATCH /api/v1/feeds/{feedId}`: 작성자가 보낸 `visibility`로 변경한다. 생략하면 기존 값을 유지한다.
- `DELETE /api/v1/feeds/{feedId}`: 기존 게시글 삭제 API를 유지한다.

새 글의 선택값은 `GET /api/v1/settings/privacy`의 `feedVisibility`로 초기화하고, 수정 화면은 해당 게시글의 값을 사용한다. 게시글별 선택은 계정의 기본값을 변경하지 않는다. 설정 조회에 실패하면 사용자가 공개 범위를 직접 선택한 뒤 게시할 수 있다.

비공개 계정의 게시글 조회 제한도 기존 서버 정책을 유지한다. `PUBLIC`을 선택하더라도 비공개 계정의 글을 모든 사람에게 공개하지 않는다.

프런트엔드 임시 작성 상태에 공개 범위를 함께 보관하므로 사진 태그 화면을 다녀오거나 제출에 실패해도 선택이 유지된다. 새로고침하면 임시 작성 상태는 기존 동작대로 초기화된다.

검증: `FeedEditIntegrationTest`에서 계정 기본값과 명시한 값으로 생성, 수정 후 재조회, 팔로우 관계와 작성자 여부에 따른 접근 제한, 계정 기본값 보존을 확인한다. 테스트 데이터는 트랜잭션 롤백한다.
