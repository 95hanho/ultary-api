# DB 태그와 일반 AI 태그 통합 추천

- `GET /tags/recommend?q=내용&limit=10`의 기존 배열 응답을 유지한다. 추천 상한은 기존 5개에서 10개로 늘렸다.
- 사용 가능한 DB 태그 후보를 최대 100개(기존 사용량·최신순) 가져온다. 승인된 상품 태그의 제목·설명도 Gemini에 JSON 데이터로 전달한다. 소규모 포트폴리오 데이터를 기준으로 한 상한이며 태그가 크게 늘면 후보 검색을 별도로 개선해야 한다.
- Gemini는 내용과 관련 있는 기존 태그 최대 5개와 일반 추천 최대 5개를 같은 요청에서 선별한다. 인기만 있고 내용과 무관한 상품은 선택하지 않도록 지시한다. 실제 관련성은 AI 판정이다.
- 작성·수정 화면은 선택한 펫 ID를 `selectedPetIds=1,2`로 보내고 수정 중이면 `editFeedId`도 보낸다. 서버가 펫 소유권/게시글 수정 권한을 검사하고 DB의 이름·종(CAT/DOG/ETC)·품종을 프롬프트에 함께 전달한다. 100번 계정의 타인 게시글 수정은 원래 작성자의 펫을 기준으로 한다.
- 고양이만 선택하면 반려견·강아지 등 명확한 반대 종 태그와 반려견 전용 상품 후보를 서버에서도 제외한다(반려견만 선택한 경우 역으로 적용). 공용 상품과 개·고양이 혼합 선택은 허용한다. 모든 품종/상품의 의미를 완벽하게 판별하는 규칙은 아니며 상세 관련성은 AI가 판단한다. 펫 미선택 시 기존 본문 기반 추천을 유지한다.
- 펫 선택이 바뀌면 진행 중이던 이전 추천 응답과 표시 목록을 무효화해 다른 펫 기준 결과가 남지 않게 한다.
- 기존 후보로 반환한 이름이 실제 제공한 후보인지 검사한다. 일반 추천 중에도 DB의 같은 태그가 있으면 기존 `tagId`로 연결한다. 이때도 삭제·거절·미승인 상업 태그는 제외한다.
- 결과를 DB 태그 먼저, 신규 일반 태그 뒤로 정렬하고 대소문자를 구분하지 않고 중복을 제거한다. 최종 `limit`은 정렬 후 적용한다. 본문에 이미 넣은 태그는 기존 FE 로직대로 숨긴다.
- AI 모델·thinking·timeout·fallback 설정은 유지한다. 추천 호출은 총 3회 시도하고 실패 로그/503 안내를 유지한다. 정상 결과가 비었을 때 기존 DB 검색으로 보완하는 동작도 유지한다.
- DB 변경이나 추천 태그의 사전 저장은 없다. 새 태그는 기존 작성 처리 시 저장한다. FE·BE 함께 반영한다.
