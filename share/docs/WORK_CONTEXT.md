# ULTARY 작업 이력

## 2026-10-27 DM 진입 시 첫 안읽은 메시지 중앙 배치

- 메시지 최초 조회 응답에 읽음 처리 전 firstUnreadMessageId를 추가했다. 이전 페이지/안읽은 메시지 없음은 null이며 DB 변경은 없다.
- FE는 해당 메시지가 포함될 때까지 이전 페이지를 조회하고 최초 진입 시 중앙에 배치한다. 아래 공간이 부족하면 하단으로 제한하며 안읽은 메시지가 없으면 하단으로 이동한다.
- 이전 대화 추가 시 위치 유지, 위쪽 대화를 읽는 동안 수신 메시지로 강제 이동 방지, 직접 발송 시 하단 이동을 적용했다.
- DM BE 통합 테스트 10개와 FE 회귀 테스트 8개, lint/타입 검사·FE 운영 빌드·BE bootWar 통과. 임시 브라우저 화면에서 중앙 배치·3개 하단·이전 대화 위치 유지·수신/발송 동작 확인 후 임시 화면을 제거했다. FE/BE 모두 배포 필요.

## 2026-10-27 FE 운영 타입 검사와 개발 생성 타입 분리

- .next/dev/types/routes.d.ts에 중복/깨진 선언이 남아 운영 빌드의 TypeScript 검사가 실패한 것을 확인하고 개발 생성 타입 디렉터리만 재생성 가능 상태로 정리했다.
- tsconfig.build.json은 기본 설정을 상속하고 .next/dev만 제외한다. Next 운영 빌드에서 해당 설정을 사용하며 개발은 기존 tsconfig.json을 유지한다.
- strict/noEmit 및 소스 390개 검사 범위를 유지했으며 ignoreBuildErrors를 사용하지 않는다. 전체 lint 0 errors/0 warnings와 운영 빌드 통과.

## 2026-10-27 추가 DB 정리 및 읽은 알림 축소

- 사용자 승인으로 만료 토큰 233개·삭제된 빈 게시글 25개·빈 DM 방 2개·AI 샘플 1개/연관 로그 5개를 백업 후 삭제했다.
- 최종 확인된 알림 정책: 전부 읽은 유저만 최신 5개를 읽음으로 유지. 유저 101/102의 알림 138개 삭제, 다른 유저/안읽은 알림 172개는 그대로 보존했다. CDN 102개·유효 토큰 24개 유지, FK 누락 없음.

## 2026-10-19 · Cursor → Codex

- 앞으로 ULTARY 개발은 Cursor에서 Codex로 전환하여 이어간다.
- `ultary-api`(Spring Boot Backend)와 `ultary-web`(Next.js Frontend + BFF)은 하나의 서비스이므로 함께 확인한다.
- 판단 기준은 미커밋 변경을 포함한 현재 코드와 최신 `share/` 문서다. Git 이력은 설계 변화와 개발 의도를 이해하는 참고자료로 사용한다.
- `share/`는 두 저장소에 동일하게 미러링하는 공통 Source of Truth다.
- 이번 체크포인트는 Gemini 태그 추천·게시글/댓글/답글 모더레이션, 최근 검색 태그 이력, 공통 태그 카탈로그, 본문 100자 제한(schema v31)까지 포함한다.
- Codex는 두 저장소의 구조와 연동 관계를 분석했다. 발견한 불일치는 아직 수정하지 않았으며, 실제 수정은 사용자 확인 후 시작한다.
- 피드 수정의 form/JSON 불일치, 펫 태그 승인·거절 Spring API 누락, 공유 피드의 게스트 처리·파일 접근, 단건 피드 차단 검사, 이전 공통 타입을 우선 확인한다.
- 스토리 24시간 만료는 테스트 목적으로 비활성화되어 있다. 실제 SMS 발송과 `/write/*`, 공통 `/settings` API는 미완성이다.
- 이번 인계·커밋 작업에서는 빌드·테스트·DB 마이그레이션·실제 Gemini 호출을 실행하지 않았다. 실행 검증과 실제 DB schema v31 적용 여부 확인은 별도 작업이다.
