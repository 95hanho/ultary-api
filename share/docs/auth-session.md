# 로그인 세션·재발급 재시도

2026-10-21 적용. 회원 및 관리자에 동일한 정책을 적용한다.

서버 통신 보강: 일반 요청·토큰 재발급·로그아웃 모두 BFF 공유 키를 전달한다. local은 HTTP 허용, prod는 HTTPS 필수이며 키는 사용자 JWT와 별개다. [`bff-server-auth.md`](./bff-server-auth.md)를 따른다.

## 재발급 중 서버 장애

- BFF만 Spring 재발급을 호출한다. 기존 인스턴스 내부 Promise 공유를 유지한다.
- 네트워크 실패·timeout·5xx·408·429·토큰이 누락된 성공 응답은 일시 장애로 분류한다. 최초 요청 후 **2초 대기하여 재시도, 다시 2초 대기하여 마지막 재시도**: 최대 3회 요청.
- BFF가 한 요청 안에서 재시도를 완료한다. 대기 중 브라우저로 중간 401을 보내지 않는다. 각 시도의 연결/응답 timeout은 4초로, 최대 대기 시간은 약 16초다.
- 중간에 성공하면 쿠키를 갱신하고 원래 요청을 계속한다.
- 모두 실패하면 요청한 정책대로 **401 `REFRESH_RETRY_EXHAUSTED` + 해당 회원/관리자 인증 쿠키 삭제**로 전환한다.
- 실제 Spring 401/403 또는 다른 비일시적 4xx는 바로 인증 실패 처리하며 재시도하지 않는다.
- 일반 로그인 POST나 업무 API 자체를 무조건 재전송하지는 않는다. 아래의 만료 Access 복구 조건을 만족할 때에만 업무 요청을 한 번 재시도한다.

## 재발급 경쟁·응답 유실 복구 (v34)

- 회원/관리자 재발급과 로그아웃은 해당 계정 DB 행을 `FOR UPDATE`로 먼저 잠근다. 토큰 조회와 교체 이력 저장은 같은 트랜잭션이다. 여러 Spring/BFF 인스턴스에서도 같은 DB 잠금을 사용한다.
- 기존 토큰 행에는 `replaced_by_token_id`, `rotated_at`을 기록한다. 새 토큰 INSERT와 기존 토큰 폐기는 함께 커밋/롤백한다. 조건부 교체 갱신 건수도 확인한다.
- **최초 이전 토큰의 회전 후 20초** 내 중복 요청은 같은 세션의 활성 후속 Refresh Token을 돌려준다. 응답 유실 후 재전송에도 적용된다. Access JWT는 새로 발급하며, 새 Refresh Token 행을 추가하지 않는다.
- 후속 토큰이 다시 교체되었다면 최대 8단계까지 추적한다. 원래 이전 토큰의 20초 창을 연장하지 않는다. 소유자·세션 일치를 검증하며 다른 세션, 만료된 토큰, 이미 로그아웃/보안 조치로 폐기된 세션은 복구하지 않는다.
- 20초는 기존 재시도 최대 약 16초를 수용하는 제한적 재사용 창이다. 이 기간에는 이전 Refresh Token 소지자도 같은 세션을 복구할 수 있다는 절충이 있다. 무기한 재사용을 허용하지 않는다.
- 방금 회전된 이전 토큰으로 로그아웃한 경우에도 같은 제한 안에서 후속 세션을 찾아 해제한다. 다른 기기 세션은 유지한다.

## 만료 Access Token 복구

- 공통 Spring 호출에서 **Authorization Bearer가 있는 요청의 HTTP 401 + `code=TOKEN_EXPIRED`**만 복구한다. 일반 401, INVALID_TOKEN, 계정 정지/탈퇴, 403, 서버 장애는 이 경로로 업무 요청을 재시도하지 않는다.
- 해당 회원/관리자 Refresh 쿠키로 재발급하고 새 토큰을 응답 쿠키에 저장한 후, 원래 요청의 메서드·본문·다른 헤더를 유지하여 **최대 한 번** 다시 보낸다. 같은 요청에서 이미 갱신된 Access 쿠키가 있으면 우선 재사용한다.
- 재발급 실패는 기존 정책대로 해당 인증 쿠키를 해제하고 401로 반환한다. 두 번째 업무 요청의 실패는 반복 복구하지 않는다.
- Spring의 `application/problem+json`도 JSON으로 파싱해 TOKEN_EXPIRED 코드를 보존한다. JSON 및 FormData 본문은 JWT 인증 단계에서 거절된 경우에만 재전송된다.
- 초기 세션 재발급 쿠키는 BFF 핸들러 실행 전에 반영하여, 핸들러 안에서 더 최신 토큰으로 복구한 결과를 예전 토큰으로 덮어쓰지 않는다.
- 쿠키를 변경할 수 있는 BFF Route Handler 경로에서 적용한다. 공유 피드 Server Component의 직접 조회는 `recoverExpiredAccess=false`로 명시하여 렌더링 중 토큰을 회전하거나 응답 쿠키를 쓰지 않는다. BFF의 공유 피드 API 호출에는 복구가 적용된다.

## 로그인 정보 저장

`ultary_token`에 다음 정보를 저장한다. 기록은 삭제하지 않고 토큰 갱신/폐기 이력을 남긴다.

| 컬럼 | 의미 |
|---|---|
| `owner_type`, `user_no`, `admin_no` | 로그인한 회원/관리자 계정 |
| `session_id` | 로그인할 때 생성한 UUID. 재발급 간 동일하며 로그인마다 다름 |
| `logged_in_at` | 최초 로그인 시각. 재발급 시 보존 |
| `connect_ip`, `connect_agent` | 최초 로그인 요청의 IP와 브라우저 User-Agent. 재발급 시 보존 |
| `created_at` | 해당 토큰 발급 시각. 세션의 최근 토큰 발급 시각 확인 가능 |
| `expires_at`, `is_revoked`, `revoked_at` | 토큰 만료·폐기 상태 |
| `replaced_by_token_id`, `rotated_at` | 교체 토큰 및 교체 시각. 중복 재발급 복구에 사용 |

일반/관리자/구글/카카오 로그인에서 BFF가 브라우저 요청의 User-Agent와 전달된 클라이언트 IP 헤더를 Spring에 전달한다. 신뢰 프록시의 X-Forwarded-For/X-Real-IP 설정이 전제이며, 이 값을 인증이나 세션 동일성의 증거로 쓰지 않는다. 이전 BFF IP/Agent 기록은 소급 복원할 수 없다.

JWT에는 발급별 무작위 `jti`를 추가해 같은 초에 같은 계정으로 로그인해도 토큰이 같아지지 않게 한다. Refresh JWT에는 세션 ID도 포함하지만, 로그아웃 대상은 JWT 서명 검증 후 DB 조회로 결정한다.

## 현재 세션 로그아웃

Spring:

- `POST /api/v1/auth/logout`: JSON `{ "refreshToken": "..." }`
- `POST /api/v1/admin/auth/logout`: 같은 JSON 형식, 관리자 Refresh Token만 허용
- Access Bearer 없이 호출 가능하다. Refresh Token 서명·만료·타입·소유자를 Spring이 검사한다. 회원/관리자 토큰을 교차 사용할 수 없다.
- 해당 소유자 + `session_id`가 일치하는 토큰만 폐기한다. IP/Agent가 같더라도 다른 세션은 건드리지 않는다.
- 이미 폐기된 유효 서명 토큰은 성공 응답으로 멱등 처리한다. 만료된 JWT는 401이다.
- 기존 데이터에 세션 ID가 없으면 해당 Refresh Token 행만 폐기한다. 재발급하면 세션 ID를 부여한다.
- 비밀번호 변경/계정 보안 조치의 전체 토큰 폐기는 유지한다. Access JWT를 즉시 블랙리스트 처리하는 정책은 추가하지 않는다.

BFF `/api/auth/logout`, `/api/admin/auth/logout`은 쿠키의 Refresh Token을 전달한다. Access 쿠키가 없어도 호출하며, 로그아웃을 위해 불필요한 회전을 하지 않는다. 서버 연결 실패 시에는 기존처럼 브라우저 쿠키를 삭제한다. 이 경우 서버 기록의 즉시 폐기까지 보장하지는 않는다.

## 마이그레이션·검증

- schema v33: `027_login_session.sql`, v34: `028_token_rotation.sql`. 기존 DB에는 필요한 증분 파일만 순서대로 적용하고 `001_init_schema.sql`을 실행하지 않는다.
- 기존 행에는 토큰별 UUID와 기존 `created_at`을 채운다. 기존 토큰의 문자열·만료·폐기 상태는 유지한다. 과거 회전 이력을 같은 세션으로 소급 결합하지 않는다.
- FE 이동 정책: 재로그인 후 메인 `/`. 로그인 기기 목록 페이지/조회 API는 이번에 추가하지 않는다.
- FE `npm run test:auth`: 장애·재시도·timeout·정보 전달·회원/관리자 로그아웃·만료 복구·1회 제한·오류 응답 형식·쿠키 반영 순서 검증. BE `AuthSessionIntegrationTest`: 실제 JWT/DB/보안 필터를 이용한 세션 분리·현재 세션 해제·기존 토큰 호환 검증(롤백). `TokenRotationConcurrencyIntegrationTest`: 별도 스레드/DB 트랜잭션에서 동시성·유예 만료·다른 세션/로그아웃된 세션 복구 차단 검증(생성한 테스트 계정과 토큰만 정리).
- 검증 결과: BFF 키 보강 이후 FE 인증 테스트 37개, BE 세션 테스트 5개·경쟁 테스트 8개·기존 관리자 인증 테스트 6개·BFF 보안 테스트 16개 통과. FE TypeScript 통과, 변경 파일 ESLint 오류 없음. 연결된 DB에 v34까지 증분 적용 완료. 실제 브라우저 로그인/재시작을 이용한 종단 검증은 수행하지 않았다.
