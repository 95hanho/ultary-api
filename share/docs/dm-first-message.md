# DM 첫 메시지 전송 시 방 생성

`/dm`에서 새 메시지 상대를 선택했을 때 기존 방이 없으면 프런트 상태로만 빈 대화 화면을 연다. 입력하지 않거나 입력 후 뒤로 나가도 방·메시지를 저장하지 않는다. 방 번호가 없으므로 읽음·보는 중·입력 중 API도 호출하지 않는다.

첫 메시지 또는 공유 콘텐츠 전송 시 `POST /api/v1/dm/rooms/start` (BFF `/api/dm/rooms/start`)를 호출한다.

- 요청: targetUserNo, body, feedId, feedMediaId, storyId. body/공유 규칙은 기존 메시지 전송과 동일하다.
- 응답: room(기존 DmRoomItemResponse), message(기존 DmMessageResponse).
- 방 생성/재사용과 첫 메시지 저장은 같은 트랜잭션이다. 메시지 검증·공유 콘텐츠 검증·권한 검증 실패 시 방 생성 및 재입장도 롤백된다.
- 같은 상대의 기존 방은 재사용한다. 새 메시지 선택 시 기존 방이 있으면 기존 입장 API로 연다.
- 첫 전송이 성공하면 실제 방 경로로 이동한다. 실패하면 입력을 유지하고 오류를 표시하며 재시도할 수 있다.
- 후속 메시지는 기존 POST /dm/rooms/{roomId}/messages를 사용한다. 팔로우·차단 정책 및 웹소켓 전송은 유지한다.

기존 POST /dm/rooms는 다른 호출처를 위해 유지한다. 기존의 빈 방을 삭제하는 작업은 포함하지 않는다. DB 구조 변경은 없다.
