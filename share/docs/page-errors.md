# 페이지 오류 숫자 및 API 오류 코드

2026-10-23 적용. 회원 페이지의 401은 로그인 이동을 유지한다.

| 상태 | 화면/의미 |
|---|---|
| 403 | 접근 권한 부족. 404로 변환하지 않고 숫자 403 표시 |
| 404 | 존재하지 않는 URL·리소스. 기존 공통 not-found 화면 |
| 500 | 서버 내부 오류 또는 원인을 분류할 수 없는 예외 |
| 502 | 업스트림 통신 실패·브라우저 네트워크 오류 |
| 503 | 서비스 이용 불가·재발급 장애 재시도 소진 |
| 504 | 서버/브라우저 요청 시간 초과 |

403 및 서버 오류 화면에는 숫자를 추가하며 기존 일시 오류 문구와 새로고침 버튼을 유지한다. API의 410은 기존 삭제 리소스 정책에 따라 404 화면으로 안내한다. 일반 회원·공유 피드·공개 울타리·관리자 조회에서 전달받은 오류 상태를 보존한다. 상태 정보가 없는 예외는 500으로 분류한다.

BFF 공통 오류 응답에 HTTP 응답과 일치하는 숫자 status 및 문자열 code를 포함한다. Spring의 기존 code(USER_NOT_FOUND, TOKEN_EXPIRED 등), message, detail, data는 유지하며 code가 없으면 HTTP 의미에 맞는 코드를 채운다. 예: HTTP 503 / {"status":503,"code":"REFRESH_RETRY_EXHAUSTED","message":"REFRESH_RETRY_EXHAUSTED"}. Spring 직접 응답은 기존 HTTP 상태와 ApiResponse/ProblemDetail의 code 구분을 유지한다.

브라우저에서 HTTP 응답을 받지 못하면 내부 status=0을 화면에서 네트워크 오류 502, REQUEST_TIMEOUT 504로 구분한다. 페이지 숫자는 API 실패의 상태를 표시하는 것이며, 클라이언트 렌더링 이후 발생한 오류가 이미 전송된 HTML 문서의 HTTP 상태를 바꾸지는 않는다. 프로덕션 서버 예외 경계에서 세부 오류가 제거된 경우에도 기본 500으로 처리한다.

인증·Refresh 쿠키 보존 정책은 auth-session.md를 유지한다. 테스트용 미리보기 경로는 검증 후 제거하며 DB 변경은 없다.
