# ULTARY 운영 빌드·배포 인계 프롬프트

작성일: 2026-10-25 (Asia/Seoul)

아래 내용을 작업 지시로 사용해 ULTARY의 배포 준비를 이어가 주세요. 자연어 설명·진행 상황·명령 승인 사유는 한국어로 작성하세요.

## 목표와 시작점

사용자는 주요 사용자 흐름 통합 검증을 완료했다고 확인했습니다. 다음 작업은 최종 운영 빌드, 운영 설정 점검, 서버 배포와 배포 후 핵심 흐름 검증입니다. 기존 통합 검증을 처음부터 반복하지 말고 마지막 코드 변경의 회귀 검사와 배포 환경 차이를 확인하세요.

완료한 통합 검증: 회원가입·로그인 → 게시글 작성·수정과 AI 정상/차단/장애 → 공개 범위·방향별 차단 → DM → 신고·관리자 조치·알림/메뉴 숫자.

기존 HOME_HANDOFF.md·WORK_CONTEXT.md의 과거 «다음 작업: 통합 검증»보다 이 문서와 현재 코드가 우선입니다. 최종 운영 빌드·실서버 배포는 아직 완료했다고 간주하면 안 됩니다.

## 저장소와 다른 로컬로 이동할 때

- BE: ultary-api, Spring Boot, Java 17. 이 PC 경로는 D:/workspace/java/ultary-api.
- FE/BFF: ultary-web, Next.js. 이 PC 경로는 D:/workspace/nextjs/ultary-web.
- 다른 PC에서는 실제 체크아웃 경로를 사용하세요. 현재 브랜치·최신 커밋·미커밋/미추적 파일을 양쪽 저장소에서 먼저 확인하세요.
- 2026-10-25까지의 기능 수정·새 API route·알림 링크 helper·테스트·파일 정리 및 인계 문서를 두 저장소의 커밋에 포함했습니다. 다른 PC에서는 해당 커밋이 전달됐는지 먼저 확인하세요. 로컬 커밋과 원격 push는 별개이므로 원격에 있다고 가정하지 마세요.
- 사용자 변경을 덮어쓰거나 reset하지 마세요. 각 저장소 AGENTS.md를 따르고, FE 수정 전에는 설치된 Next 문서를 읽으세요.
- share/는 양쪽 저장소에 같은 내용으로 유지합니다. 전체 상대 경로·해시를 비교하고 한쪽 최신 내용을 덮어쓰지 마세요.
- 실제 BE application*.yml 및 FE .env/.env.local/.env.production은 Git 제외입니다. 로컬별 설정은 별도로 준비하고 기존 설정을 덮어쓰지 마세요. 비밀값을 출력·문서화·커밋하지 마세요.

## 최근 변경 중 반드시 유지할 동작

- 회원가입 완료는 로그인 화면으로 이동하며 가입 완료 안내를 표시합니다. 연락처 인증 완료 시 데모코드를 지우고 로그인 입력 변경 시 안내를 초기화합니다.
- 일반/DEV 로그인·로그아웃 및 계정 전환 시 이전 계정의 울타리·DM 등 클라이언트 캐시가 남지 않도록 전체 이동으로 초기화합니다.
- DM 삭제는 본인 목록에서 숨기는 동작입니다. 기존 메시지를 삭제하지 않고 재진입 시 복원합니다.
- 게시글 작성·수정은 저장 전 동기 AI 검사, 댓글·답글은 저장 후 영속 작업으로 비동기 검사합니다. AI 호출 장애를 유해 콘텐츠 판정으로 처리하지 않습니다.
- 관리자 세 목록은 테이블이며 전체 건수 기준 내림차순 번호를 표시합니다. 상태변경 중 기존 FullScreenLoading을 표시합니다.
- AI 오류 목록은 실패가 있는 작업을 요청별로 묶습니다. 오류 코드·휴대폰·이메일 검색과 전체/태그 추천/게시글/댓글/답글 즉시 필터를 제공합니다.
- AI 목록은 연결된 작업이 있고 관리자 상태가 PENDING인 실패 항목을 먼저 표시합니다. 우선순위와 ID를 함께 커서에 적용하며 상태변경 후 첫 페이지를 재조회합니다.
- AI 상세는 상단 요청 정보와 오른쪽 관리자 전용 대상 미리보기, hr 아래 전체 시도 내역을 표시합니다. 미리보기 파일 접근은 해당 로그와 연결된 파일로 제한합니다.
- AI 삭제조치 후 유지/확인 대기로 변경하면 이 작업으로 숨긴 콘텐츠를 복구합니다. 댓글 수 중복 증가, 최신 버전 덮어쓰기, 삭제된 부모나 다른 삭제조치의 무시를 방지합니다. 확인 대기로 되돌려도 자동 작업은 SKIPPED로 유지합니다.
- 관리자 변경 결과는 작성자의 AI_MODERATION 알림 목록에 변경마다 저장하며 모달을 띄우지 않습니다. 게시글·댓글·답글 명칭은 대상 위치 링크입니다. 숨김 뒤에도 알림은 남고 실시간 콘텐츠 갱신·안 읽음 배지는 유지합니다.
- 작성 중 동기 검사에서 AI_CONTENT_BLOCKED가 발생할 때 보여주는 입력 오류 모달은 위 결과 모달과 별개이며 유지합니다.
- SMS 실발송과 스토리 24시간 만료 복원은 데모 정책상 보류 중입니다. 임의로 서비스를 확장하지 마세요.

## DB와 일회성 복구

- 현재 사용 DB는 schema v38까지 적용한 상태로 인계됐습니다. 같은 DB에는 migration을 중복 실행하지 마세요. 다른 DB는 실제 적용 상태를 확인한 뒤 필요한 migration만 순서대로 적용하세요.
- 기존 DB에 001_init_schema.sql이나 테스트 seed를 실행하지 마세요.
- 2026-10-25 사용자 승인으로 작업 71·로그 3건의 잘못된 게시글 ID를 120 → 103으로 복구했습니다. 댓글 815의 본문·삭제 상태는 변경하지 않았습니다.
- 복구 도구는 작업 완료 후 사용자 요청으로 제거했습니다. 복구 결과를 재조회하여 게시글 103 연결·본문/버전 일치·댓글 미삭제를 확인했습니다. 이 복구는 일반 migration이나 다른 DB에서 다시 실행할 배포 단계가 아닙니다.

## 이어서 수행할 순서

1. 양쪽 저장소와 전달된 파일, 실제 배포 대상, 실행 중인 서버/포트, 로컬·운영 DB 구분을 확인합니다.
2. 운영 설정을 점검합니다. FE HTTPS/WSS 주소, BE prod profile, 양쪽 BFF_INTERNAL_KEY, JWT/Gemini 설정, 업로드 경로·영속 보관, OAuth 운영 callback을 확인합니다. 개발용 로그인·휴대폰 데모모드 노출은 기존 데모 목적과 사용자 설정을 확인합니다.
3. 최종 변경에 대한 회귀 테스트와 타입/린트를 확인합니다. 기존 오류와 새 오류를 구분하고 검사를 통과시키려고 검증을 끄지 마세요.
4. FE 운영 빌드를 실행하고 npm start로 확인합니다. npm 스크립트가 환경 파일 우선순위를 관리하므로 Next를 직접 실행하지 마세요.
5. BE 테스트 결과를 확인하고 ROOT.war를 생성합니다. WAR의 설정 포함 여부와 실제 prod profile 선택을 확인해 개발용 설정이 운영에 잘못 적용되지 않게 합니다.
6. 빌드 오류가 있으면 원인을 좁혀 수정하고 관련 검사를 다시 실행합니다. 빌드 성공 전 실서버 교체를 진행하지 마세요.
7. 이전 배포본과 필요한 DB·업로드 파일의 백업/되돌리기 경로를 확보하고 요청받은 배포 대상에 반영합니다. 아직 확인되지 않은 접속정보나 배포 경로를 추측하지 마세요.
8. 배포 후 식별 가능한 테스트 계정·콘텐츠로 핵심 흐름을 짧게 재검증합니다: 로그인 유지/계정 전환 → 사진 업로드/게시글 → 실제 Gemini 연결 → DM 실시간 → 관리자 삭제/복구 → 작성자 알림 링크·메뉴 숫자. PC·모바일, HTTPS/WSS, 서버 로그도 확인합니다.
9. 실제 Gemini 호출과 기존 DB 작업을 소비하는 워커는 해당 환경을 확인한 뒤 다룹니다. 검증을 위해 기존 사용자 콘텐츠를 무작정 삭제하지 마세요.
10. 결과를 운영 빌드·자동 테스트·실제 브라우저·실서버 확인으로 구분해 보고합니다. 이후 README·데모 계정 안내·포트폴리오 스크린샷/영상 정리로 넘어갑니다. SEO·기존 mock/type 전체 정리는 별도 범위로 다룹니다.

## 명령어와 마지막 확인 상태

FE 폴더:
```powershell
npm ci
node --test scripts/test-admin-list-actions.mjs scripts/test-moderation-notice.mjs
node node_modules/typescript/bin/tsc --noEmit --incremental false
npm run lint
npm run build
npm start
```
npm ci는 의존성 준비가 필요한 경우 실행합니다. npm start는 기존 3000 포트 사용 여부를 확인한 뒤 실행하세요.

BE 폴더:
```powershell
.\gradlew.bat test --tests '*AdminAiReviewIntegrationTest' --tests '*FeedServiceModerationTest' --tests '*AdminAiLogApiTest' --offline
.\gradlew.bat bootWar
```
결과물: build/libs/ROOT.war. 저장소 README의 배포 대상은 Cafe24 Tomcat입니다. 실제 서버 환경을 확인해 적용하세요. 다른 로컬에서 Gradle 의존성이 없으면 offline 옵션은 사용할 수 없습니다.

- 가장 최근 BE 선택 테스트는 31개 통과했습니다. 테스트 fixture는 트랜잭션 롤백하며 ai.moderation.worker-enabled=false로 기존 작업 소비를 막습니다.
- FE 타입 검사, 최근 변경 파일 린트, 관리자 상태변경 테스트 7개와 알림/실시간 테스트 3개가 통과했습니다.
- 전체 FE lint는 과거 작성·댓글 컴포넌트의 Hook 오류가 보고된 이력이 있습니다. 현재 결과를 다시 확인하고 전체 통과로 추정하지 마세요.
- 최종 전체 운영 빌드와 배포 후 실제 확인은 아직 미수행입니다.
- 사용자 승인으로 BE 일회성 복구 도구 3개와 FE 미사용 src/lib/mock/dm.ts를 제거했습니다. 다른 후보는 아직 삭제하지 않았습니다. 테스트·migration·사용 중인 mock 유틸을 «이미 썼다»는 이유만으로 삭제하지 마세요.
