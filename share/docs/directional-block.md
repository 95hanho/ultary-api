# 방향별 사용자 차단 정책

A가 B를 차단한 경우:

- A는 검색(닉네임·펫 태그·최근 검색)에서 B를 찾고 B 울타리의 닉네임·집계·소개말을 확인할 수 있다. 소개말 아래의 펫·팔로우/DM 버튼·스토리/콘텐츠 탭·그리드는 렌더링하지 않고 차단한 유저입니다. 문구를 표시한다.
- B에게는 A의 검색 결과와 최근 검색을 숨긴다. A의 울타리 및 울타리 게시글 목록 접근은 USER_NOT_FOUND, 피드 접근은 FEED_NOT_FOUND, 스토리 접근은 STORY_NOT_FOUND의 일반 HTTP 404로 응답한다. 차단 여부 필드나 USER_BLOCKED 응답으로 차단당한 사실을 밝히지 않는다.
- 피드 목록은 기존 양방향 콘텐츠 차단을 유지한다. 타인의 피드에 달린 차단 관계 작성자의 댓글·답글도 SQL에서 LIMIT 이전에 제외한다. 인라인 답글과 펼친 답글에 동일하게 적용하며 차단한 작성자의 댓글에 직접 답글 조회를 시도하면 일반 댓글 404로 처리한다.
- 검색 가능한 B의 기본 프로필과 달리 A도 B의 피드·스토리 본문은 열람하지 않는다. A의 피드 직접 조회는 기존 USER_BLOCKED 403을 유지한다. 서로 차단했다면 차단당한 상태의 404 처리가 우선한다.
- 차단 직후에도 메인으로 이동하지 않고 현재 울타리에서 기본 정보 아래를 가린다. 기존 팔로우 해제·차단 해제 후 팔로우 미복구 정책은 유지한다.
- 회원 요청에서는 공개 울타리 metadata를 별도로 조회하지 않아 차단된 프로필을 SSR metadata로 노출하지 않는다. 허용된 프로필의 제목은 클라이언트가 설정하며 게스트 SEO는 유지한다.
- 비로그인은 기존 공개 계정/게시글 정책으로 조회한다. DB 구조 변경 없음.

검증: DirectionalBlockIntegrationTest와 FeedBlockIntegrationTest, NeighborBlockIntegrationTest, NeighborStoryIntegrationTest, SearchStoryIntegrationTest 총 16개 통과. 데이터는 트랜잭션 롤백. FE 회귀 테스트 103개 및 타입 검사 통과.
